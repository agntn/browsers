## Screenshot

```bash
browsers screenshot https://example.com -o page.png -p playwright
```

```text
ℹ Screenshot via playwright...
✔ Screenshot saved to /home/you/page.png
```

Full page by default. `--no-fullPage` keeps it to the viewport, `--width` and `--height` set that viewport, `-f` picks `png`, `jpeg` or `webp`.

In TypeScript it's `provider.screenshot({ url, fullPage, format, selector, waitFor, viewport })`, and the result carries the image as base64 in `data` plus its `mimeType`. A provider with `statelessScreenshot` false wants a session for that, same deal as Kernel and scrape. The CLI and the tools open one for you.

## One element

```bash
browsers screenshot https://httpbin.org/forms/post -o form.png --selector form
```

`--selector` captures the first element that matches, not the page. Cloudflare, Browserless and Playwright can do it, the flag is `elementScreenshot`. Leave the provider out and the first configured one of those gets the job. Name another one and it refuses. It won't quietly hand you the whole page and pretend.

A selector that matches nothing is the vendor's error, passed through. Browserless says `Element not found on page!`, which is at least honest.

## Wait for it

```bash
browsers screenshot https://quotes.toscrape.com/js-delayed/ -o quotes.png -p playwright --no-fullPage --waitFor .quote
```

```text
ℹ Screenshot via playwright...
✔ Screenshot saved to /home/you/quotes.png
```

A screenshot fires the moment the page loads. Fine for a static page. That one paints its quotes a few seconds later, though. Without `--waitFor` you get a lovely picture of an empty list and a `Next →` button. With it the shot waits for `.quote`, same as scrape's `--waitFor`.

Who can wait? Cloudflare, Browserless and Playwright, the flag is `screenshotWaitFor`. Provider choice works like `--selector`: leave it out and one of those three gets the job. Name Steel, Anchor, Kernel or Hyperbrowser and you get a refusal. Beats a confident shot of the wrong state:

```text
 ERROR  steel cannot wait for a selector before a screenshot. Use cloudflare, browserless or playwright, or drop waitFor.
```

On Playwright and Browserless a selector that never shows up gets 25 seconds. Then you hear its name. Playwright says `waitFor ".nope" didn't show up within 25s`. Browserless answers `408` with `waiting for DOM selector ".nope"`. The client retries a 408, so that verdict takes its time.

## For a model

`browsers_screenshot` returns the image itself, so a model that reads images sees the page. A capture whose base64 runs past 5 MB can't go back inline, so pass `path` and it writes a file instead. `path` never overwrites. An existing file is an error, not a surprise.

`selector` and `fullPage: true` together are an `InvalidInputError`. Pick one.

## PDF

```bash
browsers pdf https://example.com -o page.pdf -p playwright
```

```text
ℹ Generating PDF via playwright...
✔ PDF saved to /home/you/page.pdf
```

Cloudflare, Browserless and Playwright print PDFs. `--landscape` turns the page. `browsers_pdf` always writes to `path`, because a PDF can't go back to a model anyway, and an existing file is still an error.
