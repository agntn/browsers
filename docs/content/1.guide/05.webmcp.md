Ask a page through the tools it offers agents. WebMCP gives you a way to discover those tools and call them with JSON input. Radar can hand you its own search instead of making you scrape HTML and guess what its search box does. That's a much nicer conversation.

## What is WebMCP?

A page registers a tool with `document.modelContext.registerTool({ name, description, inputSchema, execute })`. Each tool has a name, a description, and a JSON schema for its input. The page can also provide hints.

Use `browsers_webmcp_tools` to list a page's tools and `browsers_webmcp_call` to run one. Both are available to agents. The [agents guide](/guide/agents) covers agent use.

WebMCP works with [Cloudflare](/providers/cloudflare) only, for now. Chromium is the default engine. Use `--browser kitesurf` in the CLI or `browser: "kitesurf"` with an agent to use Cloudflare's Kitesurf engine. Both engines gave the same answer on Radar.

## How do I list a page's tools?

The list waits for the page to load, then waits for tools to stop arriving. Some pages register them a second or so after load. Here the output limit cuts the list short:

```bash
browsers webmcp-tools https://radar.cloudflare.com/ --max-chars 700
```

```text
[provider=cloudflare] https://radar.cloudflare.com/: 6 WebMCP tools

set-location
  Filter Radar to a country, region, continent, or ASN (e.g. 'US', 'europe', 'AS13335'). Pages that can't be filtered by that location redirect to one that can.
  input: {"type":"object","properties":{"location":{"type":"string","description":"Country code, region/continent slug, or ASN."}},"required":["location"]}

[truncated 1732 of 2061 characters]
```

The full list contains `set-location`, `set-date-range`, `navigate-to`, `search`, `set-theme`, and `get-current-view`. Radar marks `search` and `get-current-view` as read-only and as containing untrusted content.

A page without WebMCP returns an empty list, not an error:

```bash
browsers webmcp-tools https://example.com --browser kitesurf
```

```text
[provider=cloudflare] https://example.com: no WebMCP tools. The page registered none once it loaded.
```

## How do I call a page tool?

Pass the tool name and JSON input. Radar's search answers with its own links:

```bash
browsers webmcp-call https://radar.cloudflare.com/ search --input '{"query":"1.1.1.1"}'
```

```text
[provider=cloudflare] https://radar.cloudflare.com/ search:

## Pages and Sections
- Start a scan of https://1.1.1.1/ (/scan?url=https://1.1.1.1/)
- Check 1.1.1.1 for post-quantum TLS key exchange support (/post-quantum?host=1.1.1.1#website-support)
- 1.1.1.1 Resolver (/dns)
- DNS cache hit ratio (/dns#dns-cache-hit-ratio)
- DNSSEC client awareness (/dns#dnssec-client-awareness)
- End-to-end security (/dns#end-to-end-security)
- DNSSEC validation status (/dns#dnssec-validation-status)
- Geographical distribution (/dns#geographical-distribution)
## IP Address
- 1.1.1.1 (/ip/1.1.1.1)
## Events
- Issues with 1.1.1.1 public resolver · WORLD · Jul 14, 2025 (/dns?dateStart=2025-07-14&dateEnd=2025-07-14)
```

When the tool answers in MCP form, `{ content: [{ type: "text", text }] }`, you get its text parts. Anything else comes back as JSON.

Both tools stop at 20 000 characters by default and say how much they cut. Use `--max-chars` in the CLI or `maxChars` for agents to change that, 200 000 at most. The list cuts between tools.

## Can a page tool change things?

Yes. `browsers_webmcp_call` can run anything the site wrote the tool to do, from a search to a setting change or a booking. Check the hints before calling. Don't run a consequential tool nobody asked for.

Hints appear next to the name as the page declares them: read-only, untrusted content, and consequential. They're the page's claims. The library doesn't check them. Treat a hint as proof? Bad bet.

Every call opens a fresh browser and closes it afterwards. The list shows tools present once the page has loaded and registration has settled. A tool added only after another tool runs never shows up. Changes in one tab don't carry over to the next call.

A tool waiting for a person to click "confirm" never answers. The call gives up after 60 seconds. That's a long wait for someone who isn't coming.

## What happens when a tool fails?

A name the page doesn't have is refused, with the available names in the response:

```bash
browsers webmcp-call https://radar.cloudflare.com/ book-flight
```

```text
https://radar.cloudflare.com/ has no WebMCP tool "book-flight". It has 6: "set-location", "set-date-range", "navigate-to", "search", "set-theme", "get-current-view". Call browsers_webmcp_tools to see them.
```

If a page tool throws, the response includes its message as `Page tool "<name>" failed: <its message>`.
