::provider-facts{name="hyperbrowser"}
::

Hyperbrowser does a lot through `/api/web/fetch`: markdown for `scrape()`, a stored image for `screenshot()`, both without a session. It answered fastest in the recording. An earlier recording caught it serving an older example.com, heading and all. This one has the current page.

Crawl and extract are jobs. The package starts one, polls it for up to two minutes, and if it's still running hands back the job ID instead of giving up. See [Crawl and search](/guide/crawl).

`search` goes to `/api/web/search`.

A page that fails to load comes back from Hyperbrowser as HTTP 200 with `status: "failed"`. The package turns that into an error, so an empty `data` never passes for an empty page.
