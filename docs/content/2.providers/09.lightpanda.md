---
title: Lightpanda
description: A local headless browser with no key or bill, plus a cloud option
---

::provider-facts{name="lightpanda"}
::

Want a real browser without a key? Lightpanda runs locally, with no bill. It's a headless browser written from scratch, not a Chromium build. No key. No account. No paint.

Choose it explicitly with `-p lightpanda` or `provider: "lightpanda"`. Playwright comes before it in the registry and needs no key either. Without a provider choice, the call never reaches Lightpanda.

Which mode do you get? A token selects Lightpanda Cloud. Set `LIGHTPANDA_API_KEY` or `LPD_TOKEN`, the name Lightpanda uses. Cloud defaults to `https://euwest.cloud.lightpanda.io`. Set `baseURL: "https://uswest.cloud.lightpanda.io"` for the US region.

Without a token, Lightpanda runs locally. It uses `LIGHTPANDA_EXECUTABLE_PATH`, or `lightpanda` on your `PATH`. If the binary is missing, the error points to https://lightpanda.io/docs.

A scrape without a session uses `lightpanda fetch --json` locally or `POST /api/fetch` in the cloud. When you ask only for markdown, Lightpanda supplies its own markdown dump. `browsers_scrape` always asks for that. Otherwise, you get the DOM as HTML.

Need a session or `waitFor`? Those use CDP through `playwright-core`, as do `navigate`, `evaluate`, and `links`. Local sessions start a `lightpanda serve` on a free loopback port. `releaseSession()` stops it. A `links` or `waitFor` call without a session starts and stops its own server. `browsers session -p lightpanda` releases its session before it exits, so no `lightpanda serve` hangs around.

Already running a server? Set local `baseURL` to its `ws://` address. Release closes the connection but leaves your server running. Sessions expose `cdpUrl` for your own Playwright or Puppeteer. In the cloud, that URL contains your token. Treat it like a key. Cloud CDP uses Lightpanda, not Chrome.

Screenshots and PDFs? No. Lightpanda doesn't paint pages. Its PNG and PDF renderings contain text, without CSS layout or images. `screenshot()` throws `UnsupportedOperationError`, and the capability flags say false. There's no crawl either. A panda with no paint is still a browser.

A page that never loads throws `NavigationError` with Lightpanda's reason:

```bash
$ browsers scrape https://nonexistent.invalid -p lightpanda
Lightpanda couldn't load the page: CouldntResolveHost
```

The cloud tells the same story in other words. Its `/api/fetch` answers a dead host with HTTP 500 and `CouldntConnect`, and you still get `NavigationError`, not a server fault you'd retry.

A site's 404 page is content instead, with `statusCode: 404`. Local fetch accepts only `http` and `https` URLs. Other schemes raise `InvalidInputError` before the binary starts.
